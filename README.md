# evidence-guardrails

AI駆動開発における新規プロジェクトの設計・実装と既存システムの変更で、実装前後の根拠不足を検出するための小さなエージェントスキル群です。`skills/` 配下に標準的な `SKILL.md` 構成で配置しています。

## なぜ必要か

AIを使うと、実装とテストは速くなります。一方で、コード生成だけでは次の問いは埋まりません。

- どこまでが変更の影響範囲か
- 何を満たせば完了なのか
- テストが通ったことと、利用目的を満たしたことをどう区別するか
- 外部送信、永続データ、権限、rollbackが未確定なまま進んでいないか

このプロジェクトは、こうした未確定事項を「あとで確認するメモ」にせず、作業を止める条件として扱います。実装を代行するものではなく、実装へ進む前に根拠不足を見える形にするためのスキル群です。

## 4スキルに分けた理由

要求、設計、テスト、利用者確認を一枚のチェックリストに置くと、何が未確認なのか分からなくなります。そこで、このプロジェクトでは確認を4つに分けます。

1. `evidence-guardrails` は、最初に必要な確認を選びます。
2. `map-observable-boundaries` は、外部境界、状態、副作用、失敗、責任者を整理します。
3. `requirements-to-verification` は、ニーズから要求、検証方法、証拠までをつなぎます。
4. `separate-verification-validation` は、仕様どおり動くことと、利用・運用目的を満たすことを分けます。

特に、影響が不明な外部送信や永続データを、低リスクとして先へ進めないことを重視します。

## 含まれるスキル

- `evidence-guardrails`: 新規プロジェクトまたは変更の影響と証拠不足を分類し、必要な下位スキルだけを順序付ける。
- `map-observable-boundaries`: 新規設計または変更の外部境界、状態、副作用、失敗、所有者を台帳化する。
- `requirements-to-verification`: ニーズ、要求、設計判断、検証証拠を混同せず追跡する。
- `separate-verification-validation`: 仕様への適合確認と、利用・運用目的への適合確認を分離する。

## 利用

```bash
npx skills add 53able/evidence-guardrails --list
npx skills add 53able/evidence-guardrails --skill map-observable-boundaries
```

ローカルでは、対応CLIが利用できる場合に次を実行できます。

```bash
npx skills add ./ --list
```

## 検証

```bash
npm test
```

これは frontmatter、ディレクトリ名、説明文、相対パス、行数を検査し、正常・異常の完成済み証拠表fixtureに対する検査器を実行します。生成済み成果物の内容が真実であることや、LLMによる実案件評価は保証しません。`evals/` は、実案件へ適用する前の評価オラクル、比較プロトコル、ケースを保持します。

## 非対象

このプロジェクトは、SysMLの自動生成、完全な要件管理、または本番変更の自動承認を提供しません。必要な根拠がない場合は、推測で補完する代わりに `unknown` または `blocked` と記録します。テンプレートが埋まっていることは、利用目的への適合や安全性を保証しません。
