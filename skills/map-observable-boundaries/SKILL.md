# 観測可能な境界を台帳化する

## 手順

1. 新規プロジェクトの目的・制約または変更要求、対象または予定コード、既存テスト、運用資料を収集する。
2. 新規設計または変更が外部へ見せる入口、出力、永続状態、副作用、失敗、依存、所有者を抽出する。
3. `assets/boundary-ledger-template.md` を複製し、`PRJ-*` または `CHG-*` と `BND-*` の安定ID、各項目に根拠と `observed`、`inferred`、`unknown` のいずれかを記録する。
4. 入口と出力の組ごとに、成功時、失敗時、再試行時、部分成功時の振る舞いを記録する。
5. 外部副作用、データ正本、認可境界、または rollback 方針を扱う変更なら、`references/stop-rules.md` を読んで停止条件を適用する。停止条件を満たす場合は、実装案を出さず `blocked` と不足情報を記録する。
6. 完成した台帳を `scripts/validate-boundary-ledger.py <台帳ファイル>` で検査する。検査失敗時は stderr の不足項目を補完するか、根拠不在なら `unknown` として停止する。
7. 台帳から、変更可能な範囲、不明な範囲、次の調査または確認依頼を簡潔に出力する。

## 出力規約

- 観測した事実、推論、未確認事項を混在させない。
- 推論で外部契約、データ正本、権限、rollback を埋めない。
- 「安全」「完了」「影響なし」は、根拠欄と検証結果なしに記録しない。

## Error Handling

- 対象コードまたは運用資料を読めない場合は、読めない範囲を `blocked` として記録し、推測で台帳を完成させない。
- 台帳検査が失敗した場合は、`scripts/validate-boundary-ledger.py` の stderr に示された必須見出しを追加して再実行する。
